---
name: Post-error efficiency suggestions
description: After encountering failures/red errors, proactively tell the user what tools or logins would improve future efficiency
type: feedback
---

After any tool/command fails or hits a red error, proactively offer a short suggestion at the end: what to install, configure, or log in to so similar tasks become smoother next time. Keep it in a short, structured block so the user can act on it at their convenience.

**Why:** User wants to improve toolchain incrementally without being interrupted mid-task. They prefer to batch decisions about setup/installation rather than context-switch.

**How to apply:** When a command fails or a capability is missing, note what would fix it. At a natural pause point (end of the task or discussion), deliver a single short suggestion block. Do NOT ask during the task flow.
